# Liora 硬件模式

硬件模式是与电脑桌宠共用反思后端、角色状态、天气规则和渲染组件的第二个运行外壳。它面向通用 ARM64/x64 Linux 小屏设备，不绑定 Compute Module 5。

## 先不买硬件也能开发

在 Windows、macOS 或 Linux 电脑上运行：

```powershell
npm.cmd run dev:device
```

这会打开一个 800×480 普通窗口，用于完成绝大部分布局、触控尺寸和交互开发。只有麦克风驱动、扬声器、RTC、屏幕亮度、功耗和散热必须留到真机验证。

## 低预算硬件建议

优先使用手边已有的旧电脑、旧笔记本或二手 x86 小主机。它们通常比购买完整开发板、存储、电源、屏幕和转接线更省钱，并且最容易运行 Electron 与 Python。

需要购买 ARM 板时：

- 完整运行当前 Electron、Python 和本地语音模型，建议至少 4GB 内存。
- 2GB 设备可用于界面和联网反思，但本地语音应改用 `tiny` 或 `base` 模型并实测延迟。
- 512MB 设备不适合当前完整程序，只适合未来的轻量显示客户端。
- Orange Pi Zero 3 等 2GB/4GB Linux 板可以作为低成本候选，但购买前必须确认可用的 Debian/Ubuntu 镜像、显示接口和 USB 音频支持。

CM5 只在准备定制主板、eMMC 和批量产品化时再考虑，学生原型阶段不需要。

## 启动方式

在设备中安装 Node.js、Python 和依赖后：

```bash
export LIORA_PYTHON=/usr/bin/python3
npm run start:device
```

也可以设置：

```bash
export LIORA_RUNTIME=device
npm start
```

开发时使用 `LIORA_DEVICE_WINDOWED=1` 关闭 kiosk 全屏。

## 当前平台能力

| 能力 | 电脑端 | Linux 硬件端 |
|---|---|---|
| 反思、知识版本与本地数据库 | 支持 | 支持 |
| DeepSeek / 本地降级 | 支持 | 支持 |
| 角色动画 | 支持 | 支持 |
| 文字输入 | 支持 | 支持，触屏键盘取决于系统 |
| 最长一分钟的手动 Whisper 听写 | 支持 | 代码兼容，需验证 PortAudio 和性能 |
| “Hi Liora”唤醒 | Vosk 中英文双模型 | 代码兼容，需验证性能后启用 |
| 桌面透明悬浮 | 支持 | 不适用 |
| 托盘和隐藏 | 支持 | 不适用 |
| 系统通知 | 支持 | 使用屏内提醒代替 |
| 时间显示 | 不常驻 | 支持 |
| 天气显示与提醒 | 支持提醒 | 支持显示和提醒 |

电脑端把光标移到人物上即可展开功能泡泡；硬件触屏端没有悬停状态，因此轻点人物会展开功能泡泡，再选择具体功能。

## 自动定位

- “天气”泡泡中的“使用当前位置”会发起一次系统定位请求。
- 定位不是持续跟踪；缓存位置最长可复用六小时，保存时只保留两位小数。
- 坐标保存在设备本机，不发送给 DeepSeek，只用于请求天气。
- 没有 GPS 的开发板可能依赖 Wi-Fi/网络定位，也可能完全无法定位，因此 `.env` 手动坐标始终保留。
- 固定摆放的硬件只需在首次配置或搬家后重新定位。

## Linux 系统依赖

不同发行版的包名可能不同，至少需要：

- 图形桌面或 Wayland/X11 kiosk 会话
- Electron 运行依赖
- Python 3.10+
- PortAudio 与可被 `sounddevice` 识别的输入设备
- ALSA/PipeWire 音频输出
- 网络和正确的系统时区

RTC 应由 Linux 设置为系统时间来源。Liora 只读取系统时间，不直接绑定某一种 RTC 芯片。

## 尚未包含的产品化能力

当前硬件模式是可运行的软件原型，不代表已经具备量产条件。以下内容仍应在确定具体硬件后实现：

- Linux 设备端 Vosk 唤醒的性能调优与默认启用
- GPIO 实体按键、物理麦克风静音与指示灯
- 环境光和屏幕亮度驱动
- 断电保护与只读系统分区
- systemd 看门狗和异常自动恢复
- 签名 OTA 更新、恢复出厂设置和首次配网
- 跨设备加密同步与重复提醒协调
